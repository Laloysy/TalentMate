## 新功能

### 1. 关注等级：让人来决定谁是重点

此前「高优先级 / 需关注」只由「多久没联系」推算，无法体现"谁对我更重要"。
现在每个联系人可以标记 **重点关注 / 普通 / 低优先**，等级会**缩放提醒阈值**：

| 等级 | 员工（需关注 / 高优先级） | 候选人（需关注 / 高优先级） |
|---|---|---|
| 重点关注 | **18 / 27 天** | 4 / 8 天 |
| 普通 | 30 / 45 天 | 7 / 14 天 |
| 低优先 | 45 / 68 天 | 11 / 21 天 |

效果：同样是 20 天没联系，普通员工还算"正常"，**重点员工已经进入"需关注"**。

### 2. 自定义阈值：HR 自己定天数

除三档预设外，还可以给单个联系人填 **需关注天数 / 高优先级天数**（1–365）。
留空则沿用等级预设；只填一项也可用。

校验：高优先级天数必须大于需关注天数，否则拒绝保存。

### 3. 界面

- 名册列表与联系人详情显示「重点关注」徽标
- 同一状态下，重点联系人排序靠前
- 关系状态的说明文案带上等级，例如「重点联系人 · 20 天未 1对1」
- 手机端与网页端都支持

## 修复

| 问题 | 说明 |
|---|---|
| 提醒邮件无限重试 | 发信失败后 `reminded` 永不置位，同一封退信邮件每 15 秒重发一次（实测 240 次/小时、480 条错误日志），且同批后续事件被跳过。改为逐事件捕获异常，失败也标记，并记录原因 |
| 网页版混合内容被拦 | 前端把接口地址写死为 `http://`，页面在 HTTPS 下打开时请求被浏览器拦截。现在网页走同源相对路径，原生包仍用绝对地址 |
| 桌面版退出登录 | 缺少二次确认，且未清除 `has_seen_tour` 与提醒偏好——同一浏览器换账号会跳过新手引导并沿用他人设置 |

## 已知限制

- **关怀邮件当前发不出去**：QQ 邮箱 SMTP 账号被限制（`535 Login fail`），
  需在邮箱设置中重新开启 SMTP 并更换授权码。邮件预览与草稿不受影响。
- **域名 `sytus.cloud` 被腾讯云备案拦截**，外网请使用 IP 访问；
  同时该 IP 的 TLS 证书已过期（2026-09-01），浏览器会提示证书错误。
- 生产库存在 3 组**历史重复联系人**（user 18），是查重功能上线前留下的，不影响新数据。
- 真机物理麦克风采集仍未闭环（模拟器音频不可靠），其余语音链路已验证。
